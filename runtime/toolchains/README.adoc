# Xenolith Toolchains repository

The purpose of this repository is to provide universal complete toolchain for C/C++ development with Xenolith Runtime on MacOS, Windows and Linux.

**Work in progress**: toolchains on beta stage now. It works, compiles and mostly tested.

## Hardware requirements

At least 32G RAM and 100G disk space required for full build (all hosts + all targets).

Most heavy host toolchains is windows, if it compiles - all other will not OOM too.

Release toolchains assembled on x86_64 linux, other platform were not tested for full builds.

Note: Apple hardware is required due licensing limitations to build apple hosts and targets.

## Build steps

### Download sources

Download dependencies to build

[source,sh]
----
# From runtime/toolchains
make download
----

### Build host toolchain

See README.md in host-* directory for concrete steps performed and prerequisites.

[source,sh]
----
# From runtime/toolchains
make host
----


### Build target sysroot

[source,sh]
----
# From runtime/toolchains
make target-<target-triple>
----

Supported targets:

* target-x86_64-unknown-linux-gnu
* target-aarch64-unknown-linux-gnu
* target-riscv64-unknown-linux-gnu
* target-x86_64-unknown-linux-musl
* target-aarch64-unknown-linux-musl
* target-riscv64-unknown-linux-musl
* target-unknown-ndk-linux-android - special target to use with Android NDK
* target-aarch64-unknown-linux-android
* target-armv7a-unknown-linux-androideabi
* target-i686-unknown-linux-android
* target-x86_64-unknown-linux-android
* target-x86_64-apple-macosx
* target-aarch64-apple-macosx
* target-aarch64-apple-ios
* target-x86_64-apple-ios-simulator
* target-aarch64-apple-ios-simulator
* target-x86_64-pc-windows-msvc
* target-aarch64-pc-windows-msvc

The Apple targets (`*-apple-macosx`, `*-apple-ios`, `*-apple-ios-simulator`) need
the matching Apple SDKs. On a macOS host they are located automatically through
`xcrun`. When cross-building from a non-Darwin host they must be provided under
`src/` as `MacOSX.sdk`, `iPhoneOS.sdk` and `iPhoneSimulator.sdk` (these are not
fetched by `make download` — they are extracted from Xcode / the Command Line
Tools and are subject to the Apple SDK license). The deployment targets are
`SP_MACOS_VER` / `SP_IOS_VER` in `target-apple/Makefile`. There are three iOS
sysroots: `target-aarch64-apple-ios` (device) plus the
`target-{x86_64,aarch64}-apple-ios-simulator` simulators; `make target-ios`
builds all three. On iOS the Vulkan validation layer is shipped as
`VkLayer_khronos_validation.framework` (upstream forces a framework there)
instead of a flat `.dylib`.

### Build cross host toolchains

Besides the native host toolchain (`make host`, built with a multi-stage
bootstrap for the build machine), additional host toolchains for *other*
platforms (or a simplified rebuild for the same one) can be produced by
*cross-compiling* them with the already-built native host's clang.

The overall build order is:

1. Build **one** native host toolchain for the build machine — `make host`.
   This is the only toolchain produced by a full bootstrap.
2. Build the **targets** — `make target-<triple>`. Each target sysroot already
   contains a complete libc of the required version (glibc/musl), libc++ and
   compiler-rt.
3. Build the **cross host toolchains** *from the targets* (where necessary) —
   `make host-cross-<triple>`. The cross host build reuses the native host's
   clang as the cross-compiler and, where the libc cannot be produced by clang
   alone (glibc needs GCC), the pre-built libc sysroot of the corresponding
   target. Therefore each `host-cross-*` recipe depends on the matching
   `target-*` in this Makefile.

[source,sh]
----
# From runtime/toolchains, after `make host` and the relevant `make target-...`
make host-cross-x86_64-unknown-linux-gnu     # reuses target-x86_64-unknown-linux-gnu glibc
make host-cross-x86_64-unknown-linux-musl     # musl libc is built inline (no target needed)
make host-cross-x86_64-pc-windows-msvc        # reuses the Windows SDK (xwin)
make host-cross-x86_64-apple-macosx           # reuses the macOS SDK
----

Supported cross hosts: `host-cross-{x86_64,aarch64,riscv64}-unknown-linux-{gnu,musl}`,
`host-cross-{x86_64,aarch64}-pc-windows-msvc`, `host-cross-{x86_64,aarch64}-apple-macosx`.
See the `cross/` subdirectory and `README.adoc` of each `host-*` directory.

## Sources list policy

The list of sources for source codes must be updated regularly. After the build of a new version is confirmed, the date of its update is placed next to the corresponding source in the format `revised: 22 feb 2026`.

Official sources are used, however, for sources whose access is restricted based on download region, an alternative method should be used (for example, direct download from the repository).

## Code style

Most of the build scripts here can be used both in the GNU environment and in PowerShell on Windows. For this purpose, standard commands (cp, rm, and others) are implemented as functions `rule_*`, which ensures their uniform behavior.
