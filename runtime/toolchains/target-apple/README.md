# target-apple: macOS/iOS targets, and the SDK-free `+open` variant

This directory builds Apple target sysroots for the Stappler/Xenolith toolchain.
Two flavors exist per architecture:

- **`<arch>-apple-macosx+sprt`** — the stock flavor: cross-compiles against a
  real `MacOSX.sdk` checkout. Requires the Xcode SDK,
  whose license restricts use to Apple-branded hardware.
- **`<arch>-apple-macosx+open`** — the SDK-free flavor documented here: the
  entire sysroot (headers, link stubs, runtimes, dependencies) is assembled
  from Apple's open-source releases plus a small hand-written overlay. Nothing
  from the Xcode SDK is compiled against or shipped; the real SDK is consulted
  **only as a read-only reference for validation** (constant values, export
  lists, symbol ownership). The result builds and links real GUI applications
  (runtime + runtime_window + MoltenVK) and a complete macOS host toolchain
  (clang/lld/lldb, GNU make, SPIRV-Tools, glslang, xlmake).

Entry points:

```sh
make x86_64-apple-macosx+open     # full target build + export
make aarch64-apple-macosx+open
```

Each runs: `bootstrap` → `open-sysroot.mk` (headers + stubs) → `crt1` →
`libcxx` (libc++/libc++abi/libunwind + compiler-rt with sanitizers) → the
dependency suite (`all`: openssl, curl, freetype, brotli, ... MoltenVK) →
`install-target.mk` (clean export into `$(TOOLCHAIN_TARGETS)/<triple>+open`).

## Sysroot layout

```
<triple>+open/
  include_libc/            SDK-like headers: apple-oss + overlay + c++/v1 + libunwind
  usr/include/             ONLY the bundled dependencies' own headers
  usr/lib/                 .tbd link stubs (libSystem, libobjc, libiconv, ...) ,
                           product dylibs (MoltenVK, sanitizers), crt1.o
  System/Library/Frameworks/   framework .tbd stubs + hand-written Headers/
  lib/clang/               compiler-rt builtins + sanitizer runtimes
  target.mk, toolchain.cmake
```

The `include_libc` split mirrors the Linux targets: dependency builds see it
via `-isystem`, engine modules via `-idirafter` (`TARGET_INCLUDE_DIR_LIBC`).
Only the intermediate tree carries a `usr/local/include → include_libc`
symlink (rescues hermetic sub-builds that wipe `CMAKE_C_FLAGS`, e.g. the
compiler-rt darwin builtins); the export has no `usr/local`.

Two deliberate deviations from a "copy of the SDK":

- **No system dylibs** — only `.tbd` stubs, exactly the symbols this target
  references. Links use the default two-level namespace with **no
  `-undefined dynamic_lookup`** escape hatch: an unresolved symbol is a hard
  error and a signal to extend the stubs (see below).
- **`XNU_PLATFORM_<platform>` is baked into `<sys/cdefs.h>`** at sysroot
  assembly time (`open-sysroot.mk` injects the macro after the include
  guard). Apple does the same at SDK generation via `unifdef` — the real SDK
  header contains no `XNU_PLATFORM` branches at all. Consequently no compiler
  invocation anywhere needs `-DXNU_PLATFORM_MacOSX`, and x86_64 binds modern
  conformance symbols (no legacy `$UNIX2003` suffixes) out of the box. The
  platform is derived from `SP_SYSNAME`/`SP_IOSSIM`, so a future `ios+open`
  target injects `iPhoneOS`/`iPhoneSimulator` automatically.

## Where the headers come from

Priority ladder, applied per missing piece:

1. **apple-oss checkouts** (`open-sysroot.mk`, sparse git clones pinned to the
   macOS 14.5 release tags): xnu (libsyscall, bsd, osfmk mach headers), Libc,
   libpthread, libplatform, libdispatch, libclosure (Blocks), libmalloc,
   Libinfo, copyfile, CommonCrypto, objc4, ICU, dyld, syslog (asl.h), libedit,
   ncurses (headers generated by Apple's own `MK*` scripts), Security
   (Authorization), configd, IOKit (IOKitUser + IOGraphics + xnu iokit),
   CarbonHeaders, swift-foundation (CoreFoundation headers),
   AvailabilityVersions (generated), cctools. Generated artifacts are
   reproducible in-repo: `gen-mig-headers.sh` (MIG user stubs for the five
   `_kernelrpc_`-prefixed defs), `gen-syscall-header.sh` (from
   `syscalls.master`).
2. **Hand-written minimal headers** (`open/sysroot/`, the git-tracked overlay)
   only where no open source exists — the ObjC/framework surface: AppKit,
   Metal, QuartzCore, CoreGraphics, CoreText, Network, UniformTypeIdentifiers,
   CoreServices (incl. FSEvents), plus small shims (`xpc/xpc.h`,
   `bsm/audit_session.h`, Foundation extensions). These contain **only the
   declarations actually used by real code** in this repository and by the
   host projects — they are not attempts at complete framework headers.
3. **The real SDK for validation only**: every hand-written constant, enum
   value, struct layout and every tbd symbol is checked against the SDK before
   it is added (e.g. all 87 `MTLPixelFormat` values are spelled explicitly);
   Nothing is copied. That check is no longer a manual step --
   [`tests/libc/macos-abi`](../../../tests/libc/macos-abi) re-runs it: it diffs
   the overlay's constants, struct layouts and ObjC property types against the
   SDK by compiling the same probe against both sysroots, and audits every tbd
   symbol for existence and library ownership. It runs from Linux with a stock
   clang, and prints SKIP when no SDK is reachable.

## Where the link stubs come from: the bake

All `.tbd` stubs are **generated, never hand-edited** — `gen-oss-stubs.sh`,
driven by `make -f open-sysroot.mk bake-stubs`. Inputs:

- **libsprt imports**: `llvm-nm --undefined-only` over the reference
  `libsprt.dylib` from BOTH `+sprt` targets (x86_64 contributes the
  `$INODE64`/`$UNIX2003` legacy variants, arm64 the plain names) — this is the
  set of system symbols the runtime itself needs.
- **Curated lists** `functions_x86_64.txt` / `functions_arm64.txt` /
  `functions_libm.txt`: symbols pulled in by the
  bundled dependencies and the host projects, accumulated iteratively (see
  next section) and validated against the SDK.
  **Export lists** `exports/<name>.txt`: symbols, exported from apple-oss
  libraries, validated against SDK's export lists to remove privates.
  (and empty libm)

The union is classified symbol-by-symbol into libraries with rules that
mirror the **real SDK's ownership** (verified by a full audit: every symbol
in our stubs lives in the same library as in the SDK — including quirks like
`NSRunLoopCommonModes` being a CoreFoundation export, the toll-free-bridged
`NSArray`/`NSDictionary`/... classes belonging to CoreFoundation, `NSObject`
to libobjc, `_Unwind_*` to libSystem). Symbols provided by the `exports/`
stubs or by the real llvm-readtapi products (libc++abi) are excluded rather
than duplicated. Foundation reexports libobjc + CoreFoundation, CoreServices
reexports CoreFoundation — the same umbrella structure the SDK uses, which is
why versioned alias symlinks (`libSystem.B.tbd`, `libobjc.A.tbd`, ...) and
`Versions/A/<name>.tbd` links exist: `ld64` resolves *recorded install-name
paths* when following reexports and flat-namespace transitive loads.

The bake is **idempotent and complete**: re-running it against the shipped
overlay is a no-op, and deleting every baked tbd and re-baking reproduces
them byte-for-byte. To extend a stub, add the (SDK-validated) symbol to the
right list and re-bake — never touch the tbd.

## How it was built: iterate compile → introspect → extend

The sysroot was not designed top-down; it converged by repeatedly throwing
real code at it and treating every diagnostic as a work item:

1. **Pick a real consumer** and build it against the incomplete sysroot:
   first `tests/libc` (the whole libc surface), then the runtime and the full
   `runtime_window` macOS backend (ObjC++), then progressively larger host
   projects — LLVM/clang/lld, lldb (editline/curses/Foundation/CoreServices),
   GNU make, SPIRV-Tools, glslang, and finally the engine's own `xlmake`.
   Each new consumer exercises a different slice of the platform surface.
2. **Every compile error is a missing declaration.** Resolve it down the
   ladder above: search the apple-oss trees for the authentic header first
   (often it exists somewhere unexpected — `os/log.h` in xnu's libkern,
   `asl.h` in the syslog project, exception codes in `osfmk/kern`); only if
   the piece is genuinely proprietary, write the minimal declaration by hand,
   copying its exact types/values from what the *consuming code* requires and
   validating against the SDK.
3. **Every link error is a missing export.** Before adding a symbol, confirm
   it in the SDK's tbds — both that it exists and *which library owns it*
   (a symbol added to the wrong stub links fine here but records a load
   command that would fail on a real Mac). Then add it to the curated list
   and re-bake. Symbols that don't exist in any SDK dylib (e.g. `___multc3`)
   are compiler-rt statics — the fix is in the link line, not the stubs.
4. **Introspect binaries, not assumptions.** The tools that did the work:
   `llvm-nm -u` on objects and dylibs (beware LTO: bitcode objects hide
   materialized refs like `srand` until link time), `llvm-otool -l/-L` for
   load commands and platform tags, and `llvm-objdump --macho --dyld-info`
   for *actual* symbol→library bindings — `--bind` is blind to chained
   fixups and reports nothing on modern binaries. The final audit script
   indexed every SDK tbd (432k symbols, `usr/lib/system/*` folded into the
   libSystem umbrella) and cross-checked every symbol we ship.
5. **Feed fixes back into generators, then prove reproducibility.** Ad-hoc
   fixes (a header copied by hand, a symbol patched into a staged tbd) only
   count once the stamp/bake/generator reproduces them from scratch: the
   acceptance test is `rm -rf intermediate targets` → full rebuild → zero
   errors, plus consumers linking `NOUNDEFS` on both architectures.
