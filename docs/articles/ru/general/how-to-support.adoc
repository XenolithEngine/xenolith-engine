# Помощь проекту

Мы приветствуем любую помощь проекту, материальную или посильным трудом.

## Если вы разработчик

Проект масштабный, есть много направлений, где можно приложить свои силы.

### Улучшение поддержки C

* Проверка текущих заголовков и функций на совместимость со стандартом
* Добавление пропущенных функций
* Снятие config gates: реализация функций, ранее недоступных на платформе
* Реализация новых функций (https://en.wikipedia.org/wiki/Iconv[iconv], atomics,
  https://en.cppreference.com/w/c/thread[C11 threads])
* Полная реализация Annex K (bounds-checking interfaces) для всех платформ

IMPORTANT: При работе с интерфейсом C нужно обеспечивать, в том числе, совместимость на уровне ABI.
То есть, не создавать конфликтующих символов с исходной платформой.

### Улучшение поддержки C++

Функции SPRT C++ реализованы как минимально необходимые для поддержки языка. Их можно расширить,
добавив поддержку:

* `std`-совместимых контейнеров: на текущий момент это только `string`, `vector`, `map`, `set`.
  Unordered-контейнеры не совместимы по поведению и не планировались таковыми.
* нереализованных функций метапрограммирования
* https://en.cppreference.com/w/cpp/ranges[ranges]
* hardening для функций C++
* других функций C++, не выходящих в текущий набор

При реализации нужно учитывать, что:

* exceptions никогда не будут поддерживаться — это нарушит принцип ABI-совместимости на отдельных
  платформах, необходимо обходить это ограничение другими средствами;
* контейнеры обязательно должны поддерживать аллокаторы на базе пулов памяти;
* должна обеспечиваться совместимость с полной стандартной библиотекой платформы, как минимум, на
  уровне флага `SPRT_USE_STL` (см.
  link:../../../../runtime/include/sprt/c/bits/__sprt_config.h[`include/sprt/c/bits/__sprt_config.h`]).

### Функции окон

Необходимо реализовать:

* drag-n-drop для всех платформ (и единый интерфейс к нему на основе `WindowLayer`)
* клик насквозь для отдельных участков окна (также через `WindowLayer`)
* поддержку вспомогательных окон (меню, всплывающие окна)
* полный перехват ввода

NOTE: Эта работа требует знания низкоуровневых API конкретной оконной системы.

### Общие функции движка

Многие вещи всё ещё находятся на стадии дискуссии, на которую вы можете повлиять, предложив
реализацию:

* звукового движка
* подхода к 3D-отрисовке и интеграции её в 2D-модель приложения
* поддержки контроллеров
* всего, что придёт вам на ум как необходимое для игрового движка и движка для приложений

### Поддержка других платформ и архитектур

В настоящий момент очередь на разработку поддержки такая:

1. iOS
2. https://webassembly.org/[WebAssembly]
3. BSD

Вы можете повлиять на процесс, реализовав поддержку раньше, чем команда движка дойдёт до её
реализации.

Поддержка новой платформы делится на две части:

#### Создание тулчейна

Здесь необходимо создать host-часть тулчейна, которая может собирать под данную платформу, как
минимум одну ключевую часть target-тулчейна (сюда входит сборка зависимостей). См.
link:../../../../runtime/toolchains/README.adoc[`runtime/toolchains/`] для примеров существующих
тулчейнов.

#### Поддержка libc

На стороне link:../../../../runtime/include/sprt/c[`include/sprt/c`] необходимо добавить
макросы-конфигураторы для новой ОС и архитектуры. Используйте текущую раскладку в
link:../../../../runtime/include/sprt/c/cross[`include/sprt/c/cross`] для понимания, что конкретно
нужно добавить, чтобы платформа запустилась.

После добавления необходимого в заголовки нужно обязательно проверить, что зависимости воспринимают
эти заголовки аналогично заголовкам исходной libc.
