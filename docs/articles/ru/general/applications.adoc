# Концепция приложений на основе Xenolith Runtime

Сегментация систем растёт. Новые версии ОС часто добавляют новые API и иногда удаляют старые. В мире Linux всё большую популярность имеют дистрибутивы с rolling release, где цикл обновления для пользовательских приложений не вполне предсказуем.

В идеале, ОС и базовые библиотеки должны обеспечивать обратную совместимость. Но мир не идеален, и этот принцип всё чаще нарушается.

Ответом на это стала контейнеризация  - возможность запускать приложения в строго известном окружении. Она бывает двух видов - тотальная, по принципу Docker, и местная, как в AppImage и snap.

Для пользовательских приложений Docker предполагает слишком много ограничений. Запустить графическое приложение с помощью Docker непросто. Вариант же положить все зависимости в один пакет вроде AppImage помогает, но возникает вопрос лицензирования (упаковки glibc и другие библиотек с GNU лицензией в пакет), и вопрос, какие именно зависимости упаковываются. Так, упаковка libxcb, libxkb или libwayland-client может создать конфликт уровня конфигурации с реально установленными в системе.

Xenolith Runtime это зонтичная libc, что позволяет создать для приложения контейнер без собственно контейнера. Xenolith Runtime можно представить как минимальный композитор для приложения внутри него.

Идея приложения на базе Xenolith Runtime в том, чтобы упаковать в него все зависимости и оставить на откуп среде исполнения взаимодействие с внешними системами.

Так, Xenolith Runtime и Xenolith Engine совместно предоставляют среду для создания графических приложений для ключевых ОС. При этом, взаимодействие с компонентами ОС выстраивается динамически в зависимости от версии этой ОС. При сборке не нужно знать, под какую конкретно версию ОС приложение собирается. Не нужны (по большей части) специфичные SDK платформы, установка которых не всегда тривиальна.

Проще говоря, мы снижаем число действий от загрузки набора инструментов до начала разработки настолько, насколько это возможно.

Важный аспект: кросскомпиляция, её принципы изначально заложены в процесс сборки. Xenolith Runtime стремиться к тому, чтобы иметь возможность собрать любое приложение с любой исходной платформы на любую целевую. Для этого набор инструментов разделён надвое - часть для исходной системы (host) и часть для целевой (target). Чтобы сборка работала на вашей системе, вам нужна часть host. Для сборки на конкретную систему нужна часть target от неё.

На практике, подход Xenolith Runtime аналогичен построению нового языка программирования. За тем исключением, что это не новый язык, а известный, с большим сообществом и колоссальным объёмом уже существующего кода C и С++.

Люди берут компилятор Go, Rust, интерпретатор Python, и сразу начинают писать код. Мы стремимся сделать то же самое для C и C++, и не в последнюю очередь - в разрезе графических приложений, для любой платформы.
