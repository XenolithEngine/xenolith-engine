# NuttX target

Status: **M0 (draft)** — `runtime/toolchains/target-nuttx/`.

NuttX is a **hosted** Xenolith target: the runtime uses NuttX's own libc
through `libc_wrapper` (same model as Linux/glibc and Android/Bionic). It does
not ship a second libc. This document is **how to assemble the sysroot**. The
NuttX kernel image, QEMU, and board bring-up are outside this tree.

== Triple naming

LLVM has no `OSType nuttx`, so NuttX rides in the *vendor* field; clang
`--target` stays baremetal:

[cols="1,1,2", options="header"]
|===
| STAPPLER_TARGET               | clang --target            | Use
| `aarch64-nuttx-none-elf`      | `aarch64-none-elf`        | ARMv8-A boards
| `riscv64-nuttx-none-elf`      | `riscv64-none-elf`        | RISC-V boards
| `arm-nuttx-none-eabi`         | `arm-none-eabi`           | Cortex-M/-R/32-bit -A
| `x86_64-nuttx-sim-linux-gnu`  | `x86_64-unknown-linux-gnu` | NuttX sim (Linux process)
|===

Per-board profiles are `+<board>` suffixes that select a `nuttx-export`
package. The base triple is what CI uses for compile-only checks.

== Input: a NuttX `make export`

The sysroot is **imported**, not built from scratch. Produce
`nuttx-export-<ver>.tar.gz` from a configured NuttX tree (`make export`), then
pass it as `NUTTX_EXPORT=`. The export must include:

* `CONFIG_TLS_NELEM=8` (or higher) — `pthread_key_*` slots. Default is 0.
* `CONFIG_SCHED_THREAD_LOCAL` **unset** — ELF TLS is broken on NuttX/aarch64
  (no `arm64_tls.c` / `tpidr_el0` save-restore). The target uses
  `-femulated-tls`; `__emutls_get_address` is compiled into
  `libclang_rt.builtins-aarch64.a`. Do not enable `CONFIG_SCHED_THREAD_LOCAL`.
* `CONFIG_PIPES=y` — poll reactor self-pipe.
* `CONFIG_DISABLE_ENVIRON` unset — `getenv`/`setenv`.
* `CONFIG_HAVE_CXX=y` + `CONFIG_HAVE_CXXINITIALIZE=y`. The runtime ships its
  own libc++abi (`target-nuttx/libcxx.mk`); NuttX `libxx.a` stays the mini-ABI.

Layout of the package and `import-export.mk` is in
`runtime/toolchains/target-nuttx/README.adoc`.

== Assemble `aarch64-nuttx-none-elf`

PATH: Xenolith GNU make 4.x + clang 21 first. Do **not** use Apple
`/usr/bin/make` (3.81). Do **not**
`make -C runtime/toolchains target-aarch64-nuttx-none-elf` — that Makefile's
`host` goal rebuilds clang. Invoke `target-nuttx/Makefile` directly.

=== 1. Third-party sources

Do **not** `make -C runtime/toolchains download` (Vulkan/Wayland and a full
llvm-project). Fetch only this set. Empty directories from a failed wget still
satisfy make's directory target — if `CMakeLists.txt` / `Configure` is missing,
`rmdir` and retry.

----
ENGINE=<engine-root>
TC=$ENGINE/runtime/toolchains
make -C $TC \
  $TC/src/simde $TC/src/zlib $TC/src/bzip2 $TC/src/brotli \
  $TC/src/libjpeg-turbo $TC/src/libpng $TC/src/giflib $TC/src/libwebp \
  $TC/src/freetype $TC/src/harfbuzz $TC/src/sheenbidi $TC/src/sqlite \
  $TC/src/openssl $TC/src/openssl-gost-engine $TC/src/nghttp3 \
  $TC/src/libzip $TC/src/curl
test -f $TC/src/freetype/CMakeLists.txt
test -f $TC/src/openssl/Configure
----

llvm-project: sparse cone, tag `llvmorg-21.1.8` (matches the host clang):

----
if [ ! -d $TC/src/llvm-project/compiler-rt ]; then
  git clone --depth 1 --filter=blob:none --sparse --branch llvmorg-21.1.8 \
    https://github.com/llvm/llvm-project.git $TC/src/llvm-project
  git -C $TC/src/llvm-project sparse-checkout set \
    compiler-rt cmake llvm/cmake third-party libcxx libcxxabi libunwind runtimes
fi
test -f $TC/src/llvm-project/compiler-rt/lib/builtins/emutls.c
test -d $TC/src/llvm-project/libcxx
----

savannah.gnu.org (freetype) is slow. If the dir is empty, unpack
`freetype-2.14.3.tar.xz` with `--strip-components=1` into `$TC/src/freetype`.

=== 2. Run the assemble

----
make -C $ENGINE/runtime/toolchains/target-nuttx target-aarch64 \
  NUTTX_EXPORT=<path-to>/nuttx-export-0.0.0.tar.gz
----

Order: import-export → init-target (`target.mk`, `toolchain-libs.cmake`) →
compiler-rt + `emutls.c` + SME stub → libcxxabi + libunwind → in-tree
`libsprt.a` → zlib/bzip2/brotli/jpeg/png/gif/webp/freetype/harfbuzz/sheenbidi/
sqlite/openssl/gost/nghttp3/libzip/curl → `install-target.mk`.

Success is
`$ENGINE/runtime/toolchains/target-nuttx/targets/aarch64-nuttx-none-elf/`
with at least:

* `target.mk`
* `usr/lib/libsprt.a`
* `usr/lib/libclang_rt.builtins-aarch64.a` (`nm` shows `__emutls_get_address`)
* `usr/lib/libsme_stub.a`
* `usr/lib/libc++abi.a` `usr/lib/libunwind.a`
* `usr/include/pthread.h` (from the export)

Resume is incremental. Do not `clean` unless the sysroot is corrupt.
`libcxx.mk` skips cmake if `libc++abi.a` + `libunwind.a` are already staged.
compiler-rt is cached under `intermediate/…/_compiler-rt-cache-*`.

=== 3. CLI store symlink

NuttX is **not** in the SDK catalogue. Point both lookup paths at the assemble
(`target.mk` + `usr/lib/libsprt.a`):

----
ASSEMBLE=$ENGINE/runtime/toolchains/target-nuttx/targets/aarch64-nuttx-none-elf
ln -sfn $ASSEMBLE $ENGINE/runtime/toolchains/targets/aarch64-nuttx-none-elf
mkdir -p $HOME/.local/share/xenolith/data/toolchains/targets
ln -sfn $ENGINE/runtime/toolchains/targets/aarch64-nuttx-none-elf \
  $HOME/.local/share/xenolith/data/toolchains/targets/aarch64-nuttx-none-elf
----

`xenolith-cli` looks at `$ENGINE/toolchains/targets/X` **first**. A leftover
**real directory** there is not replaced by the store symlink (missing
`libc++abi.a` / `libunwind.a`). Move it aside and `ln -sfn`.

=== 4. Compile-check

----
xenolith-cli build $ENGINE/tests/runtime \
  --engine $ENGINE \
  --target aarch64-nuttx-none-elf
----

Pass: exit 0 and `built <path> for aarch64-nuttx-none-elf (…)`. Artifact is a
**relocatable** ELF under
`$ENGINE/tests/runtime/stappler-build/aarch64-nuttx-none-elf/debug/cc/runtimetest`.

`make/os/nuttx.mk` sets `OSTYPE_EXEC_LDFLAGS := -nostdlib -Wl,-r`. Without
that, clang's `aarch64-none-elf` driver injects `crt0.o` and `-lunwind`.
`-Wl,-r` keeps kernel symbols undefined; `--gc-sections` is incompatible with
`-r`. `--run` cannot launch this target on the host. Linking the relocatable
into a NuttX image (`EXTRA_OBJS=` / `EXTRA_LIBS=`) is a board-image step, not
part of this assemble.

== Assemble gotchas

* During assemble, NuttX libc lives under `intermediate/…/sysroot/usr`;
  third-party deps under `usr/`. `target.mk` must pick libc via a
  `wildcard …/sysroot/usr/include` test and put
  `-idirafter $(TARGET_INCLUDE_DIR_LIBC)` on C/CXX flags, or `arch/setjmp.h`
  is missing while compiling `libsprt.a`. Depend `target.mk` on
  `init-target.mk` itself (`THIS_FILE`). If `arch/setjmp.h` is missing:
  `rm -f …/intermediate/aarch64-nuttx-none-elf/target.mk` and rerun.
* `toolchain-libs.cmake` must put `--target=aarch64-none-elf` **inside**
  `CMAKE_C_FLAGS_INIT`, not only `CMAKE_C_COMPILER_TARGET`. libpng
  `genout.cmake` runs `clang -E` with `CMAKE_C_FLAGS` alone; without
  `--target` Xenolith clang defaults to `x86_64-unknown-linux-gnu` and sprt
  looks up `nuttx_sprt/x86_64_sprt/config.h`. Same pattern as `target-wasm`.
  If that happens, `rm` the cmake file so `init-target.mk` regenerates it.
* Sparse `llvm-project` for libcxx needs `LLVM_INCLUDE_TESTS=Off` (no
  `llvm/utils/llvm-lit`).
* `CMAKE_SYSTEM_NAME=Generic` for compiler-rt on Darwin (the Darwin cmake
  path produces empty archives). Compile `emutls.c` **into**
  `libclang_rt.builtins-aarch64.a` (baremetal builtins omit it). Never a
  side `libemutls.a`.
* Generic cmake installs libpng as `liblibpng16_static.a` / `libpng.a`. The
  inner Makefile stamps on `libpng16.a` — `common/libpng.mk` renames it
  (same as WASM).
* Empty `runtime/toolchains/src/<lib>` directories satisfy make's directory
  target and skip the unpack. `src/freetype` with no `CMakeLists.txt` is
  this. `rmdir` and re-fetch.
* The export's `Make.defs` may carry an absolute `-Map=<nuttx-tree>/nuttx.map`.
  `import-export.mk` does not strip it; consumers that feed `NUTTX_LDFLAGS`
  into a link must filter `Map=` out.
