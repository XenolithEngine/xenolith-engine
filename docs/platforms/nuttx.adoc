# NuttX target

Status: **M0 (draft)** — `runtime/toolchains/target-nuttx/`.

NuttX is a **hosted** Xenolith target: the runtime uses NuttX's own libc
through `libc_wrapper` (same model as Linux/glibc and Android/Bionic). It does
not ship a second libc. This document is **how to assemble the sysroot**. The
NuttX kernel image, QEMU, and board bring-up are outside this tree.

== Triple naming

LLVM has no `OSType nuttx`, so NuttX rides in the *vendor* field; clang
`--target` stays baremetal:

[cols="1,1,2", options="header"]
|===
| STAPPLER_TARGET               | clang --target            | Use
| `aarch64-nuttx-none-elf`      | `aarch64-none-elf`        | ARMv8-A boards
| `riscv64-nuttx-none-elf`      | `riscv64-none-elf`        | RISC-V boards
| `arm-nuttx-none-eabi`         | `arm-none-eabi`           | Cortex-M/-R/32-bit -A
| `x86_64-nuttx-sim-linux-gnu`  | `x86_64-unknown-linux-gnu` | NuttX sim (Linux process)
|===

Per-board profiles are `+<board>` suffixes that select a `nuttx-export`
package. The base triple is what CI uses for compile-only checks.

== Input: a NuttX `make export`

The sysroot is **imported**, not built from scratch. Produce
`nuttx-export-<ver>.tar.gz` from a configured NuttX tree (`make export`), then
pass it as `NUTTX_EXPORT=`. The export must include:

* `CONFIG_TLS_NELEM=8` (or higher) — `pthread_key_*` slots. Default is 0.
* `CONFIG_SCHED_THREAD_LOCAL` **unset** — ELF TLS is broken on NuttX/aarch64
  (no `arm64_tls.c` / `tpidr_el0` save-restore). The target uses
  `-femulated-tls`; `__emutls_get_address` is compiled into
  `libclang_rt.builtins-aarch64.a`. Do not enable `CONFIG_SCHED_THREAD_LOCAL`.
* `CONFIG_PIPES=y` — poll reactor self-pipe.
* `CONFIG_DISABLE_ENVIRON` unset — `getenv`/`setenv`.
* `CONFIG_HAVE_CXX=y` + `CONFIG_HAVE_CXXINITIALIZE=y`. The runtime ships its
  own libc++abi (`target-nuttx/libcxx.mk`, built against the runtime's libc++
  port — LLVM's `libcxx` is not built); NuttX `libxx.a` stays the mini-ABI.
* `CONFIG_ARCH_SETJMP_H=y` — `setjmp`/`longjmp`. Off by default on arm64, and
  then the libc has no such symbol at all (see the unwinder section below).

Layout of the package and `import-export.mk` is in
`runtime/toolchains/target-nuttx/README.adoc`.

== Assemble `aarch64-nuttx-none-elf`

PATH: Xenolith GNU make 4.x + the SDK clang first. Do **not** use Apple
`/usr/bin/make` (3.81). Do **not**
`make -C runtime/toolchains target-aarch64-nuttx-none-elf` — that Makefile's
`host` goal rebuilds clang. Invoke `target-nuttx/Makefile` directly.

=== 1. Third-party sources

Do **not** `make -C runtime/toolchains download` (Vulkan/Wayland and a full
llvm-project). Fetch only this set. Empty directories from a failed wget still
satisfy make's directory target — if `CMakeLists.txt` / `Configure` is missing,
`rmdir` and retry.

----
ENGINE=<engine-root>
TC=$ENGINE/runtime/toolchains
make -C $TC \
  $TC/src/simde $TC/src/zlib $TC/src/bzip2 $TC/src/brotli \
  $TC/src/libjpeg-turbo $TC/src/libpng $TC/src/giflib $TC/src/libwebp \
  $TC/src/freetype $TC/src/harfbuzz $TC/src/sheenbidi $TC/src/sqlite \
  $TC/src/openssl $TC/src/openssl-gost-engine $TC/src/nghttp3 \
  $TC/src/ngtcp2 $TC/src/libzip $TC/src/curl
test -f $TC/src/freetype/CMakeLists.txt
test -f $TC/src/openssl/Configure
----

llvm-project: sparse cone, tag `$(SP_LLVM_TAG)` — it must match the host clang.
The version is pinned in exactly one place,
`runtime/toolchains/common/utils/llvm-version.mk`; `target-nuttx` derives the
resource-dir symlink (`lib/clang/$(SP_LLVM_VER)`) from the same file, so a
clone at a different tag shows up as a dangling `lib/clang/<ver>`:

----
VMK=$TC/common/utils/llvm-version.mk
LLVM_TAG=llvmorg-$(sed -n 's/^SP_LLVM_VER *:= *//p' $VMK).$(sed -n 's/^SP_LLVM_MINOR *:= *//p' $VMK).$(sed -n 's/^SP_LLVM_PATCH *:= *//p' $VMK)
if [ ! -d $TC/src/llvm-project/compiler-rt ]; then
  git clone --depth 1 --filter=blob:none --sparse --branch $LLVM_TAG \
    https://github.com/llvm/llvm-project.git $TC/src/llvm-project
  git -C $TC/src/llvm-project sparse-checkout set \
    compiler-rt cmake llvm/cmake third-party libcxx libcxxabi libunwind runtimes
fi
test -f $TC/src/llvm-project/compiler-rt/lib/builtins/emutls.c
test -d $TC/src/llvm-project/libcxx
----

savannah.gnu.org (freetype) is slow. If the dir is empty, unpack
`freetype-2.14.3.tar.xz` with `--strip-components=1` into `$TC/src/freetype`.

=== 2. Run the assemble

----
make -C $ENGINE/runtime/toolchains/target-nuttx target-aarch64 \
  NUTTX_EXPORT=<path-to>/nuttx-export-0.0.0.tar.gz
----

Order: import-export → init-target (`target.mk`, `toolchain-libs.cmake`) →
compiler-rt + `emutls.c` + SME stub → libcxxabi + libunwind → in-tree
`libsprt.a` → zlib/bzip2/brotli/jpeg/png/gif/webp/freetype/harfbuzz/sheenbidi/
sqlite/openssl/gost/nghttp3/ngtcp2/libzip/curl → `install-target.mk`.

OpenSSL is built with sockets on, so DTLS and QUIC (client and server) come
along; ngtcp2 + nghttp3 then give curl HTTP/3. That needs an export with
`CONFIG_NET=y` — with networking off the sprt libc's weak ENOSYS socket stubs
(`libc_wrapper/platform/nuttx/stubs.cc`) stand in, and NuttX's own socket
bodies are never linked.

Success is
`$ENGINE/runtime/toolchains/target-nuttx/targets/aarch64-nuttx-none-elf/`
with at least:

* `target.mk`
* `usr/lib/libsprt.a`
* `usr/lib/libclang_rt.builtins-aarch64.a` (`nm` shows `__emutls_get_address`)
* `usr/lib/libsme_stub.a`
* `usr/lib/libc++abi.a` `usr/lib/libunwind.a`
* `usr/include/pthread.h` (from the export)

Resume is incremental. Do not `clean` unless the sysroot is corrupt.
`libcxx.mk` skips cmake if `libc++abi.a` + `libunwind.a` are already staged.
compiler-rt is cached under `intermediate/…/_compiler-rt-cache-*`.

=== 3. CLI store symlink

NuttX is **not** in the SDK catalogue. Point both lookup paths at the assemble
(`target.mk` + `usr/lib/libsprt.a`):

----
ASSEMBLE=$ENGINE/runtime/toolchains/target-nuttx/targets/aarch64-nuttx-none-elf
ln -sfn $ASSEMBLE $ENGINE/runtime/toolchains/targets/aarch64-nuttx-none-elf
mkdir -p $HOME/.local/share/xenolith/data/toolchains/targets
ln -sfn $ENGINE/runtime/toolchains/targets/aarch64-nuttx-none-elf \
  $HOME/.local/share/xenolith/data/toolchains/targets/aarch64-nuttx-none-elf
----

`xenolith-cli` looks at `$ENGINE/toolchains/targets/X` **first**. A leftover
**real directory** there is not replaced by the store symlink (missing
`libc++abi.a` / `libunwind.a`). Move it aside and `ln -sfn`.

=== 4. Compile-check

----
xenolith-cli build $ENGINE/tests/runtime \
  --engine $ENGINE \
  --target aarch64-nuttx-none-elf
----

Pass: exit 0 and `built <path> for aarch64-nuttx-none-elf (…)`. Artifact is a
**relocatable** ELF under
`$ENGINE/tests/runtime/stappler-build/aarch64-nuttx-none-elf/debug/cc/runtimetest`.

`make/os/nuttx.mk` sets `OSTYPE_EXEC_LDFLAGS := -nostdlib -Wl,-r`. Without
that, clang's `aarch64-none-elf` driver injects `crt0.o` and `-lunwind`.
`-Wl,-r` keeps kernel symbols undefined; `--gc-sections` is incompatible with
`-r`. `--run` cannot launch this target on the host. Linking the relocatable
into a NuttX image (`EXTRA_OBJS=` / `EXTRA_LIBS=`) is a board-image step, not
part of this assemble.

== C++ exceptions, longjmp and the unwinder

Both work, but only if the image link cooperates - neither is self-contained in
the sysroot:

* `libunwind.a` is built for bare metal (`LIBUNWIND_IS_BAREMETAL`), so it has no
  dynamic loader to ask and finds its FDEs through four linker symbols:
  `__eh_frame_start` / `__eh_frame_end` / `__eh_frame_hdr_start` /
  `__eh_frame_hdr_end`. NuttX's linker scripts do not define them. Until the
  board's script does, `libc_wrapper/platform/nuttx/stubs.cc` supplies weak
  zeros so the link succeeds, and every `throw` dies as
  `libunwind: unsupported .eh_frame_hdr ...` followed by `terminate()`. The
  script snippet to add is quoted verbatim in libunwind's `AddressSpace.hpp`; a
  linker-script assignment outranks the weak stubs, so no source change is
  needed once it lands. `.eh_frame_hdr` is only emitted when the link gets
  `--eh-frame-hdr`; with the `SIZEOF(...) > 0 ? ... : 0` form from that snippet
  its absence just falls back to a linear `.eh_frame` scan.
* `setjmp`/`longjmp` need `CONFIG_ARCH_SETJMP_H=y` in the export
  (`libs/libc/machine/<arch>/arch_setjmp.S`); with it off NuttX ships no
  `setjmp` symbol at all. sprt's `longjmp` is the destructor-running one - it
  drives `_Unwind_ForcedUnwind`, so it needs the unwinder above as well.
  `sigsetjmp` is a statement-expression macro on NuttX, not a symbol;
  `runtime_core_setjmp.cpp` hands back plain `setjmp` and fills the mask half in
  `cfa_sigsetjmp`.

== NuttX is not Linux-ABI

`sprt/c/cross/nuttx_sprt/` was originally written as a set of one-line forwards to
`linux_sprt/`, on the assumption that NuttX follows the asm-generic layout. It does
for the errno table, the `AF_*`/`PF_*` families, most `MSG_*` bits and the `*at()`
flags — and for very little else. These forwards were replaced with real tables:

[cols="1,3"]
|===
| Header | What NuttX actually does

| `dir_ptr.h`
| `struct dirent` is `{ ino_t(32-bit) d_ino; uint8_t d_type; char d_name[CONFIG_NAME_MAX+1]; }` — no `d_off`/`d_reclen`, and the name buffer is a kconfig value.

| `fcntl.h`
| `O_*` diverges from bit 14 up (`O_DIRECTORY` is `1<<16`); `F_*` is numbered alphabetically from 0, so glibc's `F_GETFL` (3) is NuttX's `F_GETLEASE` and `F_SETFL` (4) is `F_GETLK`.

| `sysconf.h`
| `_SC_*`/`_PC_*` are alphabetical from 1; glibc's `_SC_PAGESIZE` (30) is NuttX's `_SC_COLL_WEIGHTS_MAX`.

| `polltypes.h`, `fdset.h`
| `struct pollfd` has 32-bit `events`/`revents` plus three driver-private trailing fields; `fd_set` is a `uint32_t` array sized by `CONFIG_LIBC_OPEN_MAX`, not 1024 bits of `long`.

| `sockdef.h`, `netinetdef.h`
| `SHUT_*` start at 1; the whole `SO_*` table is renumbered (`SO_REUSEADDR` is 11); every protocol-level option is `__SO_PROTOCOL + n` (`TCP_NODELAY` is 16, `IP_TOS` is 29).

| `signal.h`
| `sigset_t` is two 32-bit words; `SIG_IGN` is 0 and `SIG_DFL` is 1 only when `CONFIG_SIG_DEFAULT` is on.

| `clockid.h`, `math.h`, `mbstate.h`, `mman.h`
| `CLOCK_BOOTTIME` is 4; the `FP_*` classification order differs; `mbstate_t` is 24 bytes and `wctype_t`/`wctrans_t` are `int`; `MAP_*` are consecutive bits and `MADV_RANDOM`/`MADV_SEQUENTIAL` are swapped.
|===

This is not cosmetic. The wrappers forward flags, commands and struct pointers to
the NuttX libc without translating them, and outside `__SPRT_BUILD` these macros
*are* the `O_*`/`SO_*`/`struct dirent` the application sees, so a Linux number does
not merely go unchecked — it asks NuttX a different question. The `static_assert`
blocks in `runtime/libc_wrapper/` that used to be skipped with `#if !SPRT_NUTTX`
now run on NuttX too and are what pins all of this.

Three things follow for anyone extending the tables:

* Names NuttX does not implement are still defined (the umbrellas re-export them
  unconditionally), but moved to `0x1000`+, clear of every range NuttX assigns
  meaning to, so an unsupported request fails with `ENOPROTOOPT`/`EINVAL` instead
  of silently acting on a different option.
* Their asserts are written `#if !SPRT_NUTTX || defined(NATIVE_NAME)`, never a bare
  `#ifdef NATIVE_NAME`. A bare `#ifdef` would disable the check on *every* platform
  whose libc happens to lack the name, which is exactly what the two-sided
  `#if defined(__SPRT_X) || defined(X)` guards elsewhere in these files exist to
  prevent. Naming the OS also means the check comes back by itself if a NuttX bump
  adds the constant.
* Anything read from a kconfig (`CONFIG_NAME_MAX`, `CONFIG_LIBC_OPEN_MAX`,
  `CONFIG_SIG_DEFAULT`, `CONFIG_NET_TCPBACKLOG_CONNS`) is taken from
  `<nuttx/config.h>` directly, not from `<limits.h>`: NuttX's own headers silently
  default those, which would produce a struct that compiles but does not match the
  libc it links against.

== Hosted, not freestanding

The third-party deps for this target are compiled **hosted**, unlike the wasm and
Windows targets whose `common/configure.mk` branches pass `-ffreestanding`. That
is a correctness requirement, not a style choice.

`SPRT_UMBRELLA_REQUIRED` is defined as `(__STDC_HOSTED__ == 1)`. Hosted, each
`include_libc/<header>` entry point is an inline forwarder to the matching
`__sprt_*` symbol. Freestanding, the same header emits a bare prototype for the
**plain** name and leaves the link to resolve it. On wasm and Windows the plain
name is sprt's own `libc_impl`, so both shapes end up in the same place. NuttX
has a real libc, so the freestanding shape splits the two halves apart:

* the *type* still comes from `<sprt/c/bits/pthread.h>` — `pthread_once_t` is a
  4-byte word there;
* the *function* comes from NuttX's libc, whose `pthread_once_t` is
  `struct { volatile bool done; pthread_mutex_t mutex; }`.

NuttX's `pthread_once` then read `done` (zero, fine) and locked a mutex living
past the end of the object. The symptom was OpenSSL hanging forever inside
`OSSL_PROVIDER_load` on its first `CRYPTO_THREAD_run_once`, which is what the
`SPRT_NUTTX` gate in `stappler/crypto/SPCrypto-openssl.cc` was really standing in
for — its comment blamed a missing entropy device, but the board has one and the
device was never the problem. Every other TLS/threading user was equally exposed.

The engine itself was never affected: nothing under `make/` passes
`-ffreestanding`, so engine code always took the hosted path. That asymmetry is
why the kiosk rendered fine while libcurl/libssl were unusable.

When a NuttX hang looks like this, ask QEMU where the CPU is
(`human-monitor-command` + `info registers` over QMP). A PC inside `up_idle`
means the task is BLOCKED on a lock, not spinning; symbolize with
`llvm-addr2line` and bisect with a staged-`printf` probe linked in as `XL_APP`.

== Dep feature probes

A cmake feature probe (`check_function_exists`, `check_symbol_exists`) only
answers the question it is asked if it **links**. Compile-only, its test source
is just `char FUNC();` plus a call, so every function comes back present. The
NuttX toolchain file sets `CMAKE_TRY_COMPILE_TARGET_TYPE=STATIC_LIBRARY`
globally, which is right for deps that only probe headers and wrong for the two
that probe symbols — libzip and curl. Both raise it back to `EXECUTABLE` in
their own `CMAKE_PROJECT_<name>_INCLUDE` file
(`nuttx-{libzip,curl}-project-include.cmake`); it has to be done there rather
than with a plain `-D` because the toolchain file's `set()` is a normal variable
that shadows the cache entry.

Making the probe link is the harder half. A NuttX probe executable cannot close
on its own:

* NuttX splits its libc across archives. `malloc`/`free` are in `libmm.a`,
  `socket`/`poll`/`read`/`write`/`close`/`ioctl`/`stat` in `libfs.a`, `connect`
  in `libnet.a`, the scheduler/arch/driver glue behind them in
  `libsched.a`/`libarch.a`/`libdrivers.a`/…. A probe linked against `libc.a`
  alone reports `socket()` absent. `SP_NUTTX_PROBE_LDFLAGS` in
  `common/configure.mk` therefore links the whole set in a `--start-group`.
* What is left over is genuinely supplied at the final image link: board code
  (`board_late_initialize`), linker-script symbols (`_stext`, `_sinit`,
  `g_idle_topstack`), and the part of the sprt umbrella surface NuttX libc does
  not carry, which the engine's `libc_impl` module provides — complex math,
  wide-char, regex, `setlocale`/`nl_langinfo`, `fenv`, `setjmp`/`longjmp`,
  `stdin`/`stdout`/`stderr`. `target-nuttx/gen-probe-stubs.sh` derives that set
  mechanically (undefined-minus-defined over every staged archive, `libapps.a`
  excluded because it carries the board's own application) and emits
  `libprobe-stubs.a`: weak, 16-byte-aligned placeholders. Nothing but a probe
  ever links it, and `install-target.mk` deletes it from the shipped tree.
* `--no-dependent-libraries` drops `libunwind.a`'s embedded `-lpthread`
  specifier, which has no archive on NuttX (pthreads live inside libc).

With that in place `--no-undefined` means an unresolved symbol really is a
missing one, so curl needs no hand-written `-DHAVE_*` cache seeds: it discovers
`getaddrinfo`, `inet_ntop`/`inet_pton`, `sendmsg`, `socketpair` (all real
`libc.a`/`libnet.a`/`libfs.a` symbols) and correctly rejects `getifaddrs` and
`if_nametoindex`.

The remaining override needed is the opposite failure mode — symbol present,
declaration absent. `arc4random`/`arc4random_buf` are in NuttX's `libc.a`, but
the sprt umbrella `<stdlib.h>` does not re-declare that NuttX extension, so
libzip would emit a call to an undeclared function; `HAVE_ARC4RANDOM` is forced
to 0 in its project-include. `HAVE_STRERROR_S`/`HAVE_FSEEKO`/`HAVE_FTELLO` are
forced the other way for the same reason in reverse.

== Assemble gotchas

* During assemble, NuttX libc lives under `intermediate/…/sysroot/usr`;
  third-party deps under `usr/`. `target.mk` must pick libc via a
  `wildcard …/sysroot/usr/include` test and put
  `-idirafter $(TARGET_INCLUDE_DIR_LIBC)` on C/CXX flags, or `arch/setjmp.h`
  is missing while compiling `libsprt.a`. Depend `target.mk` on
  `init-target.mk` itself (`THIS_FILE`). If `arch/setjmp.h` is missing:
  `rm -f …/intermediate/aarch64-nuttx-none-elf/target.mk` and rerun.
* `toolchain-libs.cmake` must put `--target=aarch64-none-elf` **inside**
  `CMAKE_C_FLAGS_INIT`, not only `CMAKE_C_COMPILER_TARGET`. libpng
  `genout.cmake` runs `clang -E` with `CMAKE_C_FLAGS` alone; without
  `--target` Xenolith clang defaults to `x86_64-unknown-linux-gnu` and sprt
  looks up `nuttx_sprt/x86_64_sprt/config.h`. Same pattern as `target-wasm`.
  If that happens, `rm` the cmake file so `init-target.mk` regenerates it.
* The runtimes build (libunwind + libcxxabi) needs `LLVM_INCLUDE_TESTS=Off` on a
  sparse `llvm-project` (no `llvm/utils/llvm-lit`). `libcxx` is in the
  sparse-checkout list only for `runtime/libcxx/Makefile regen`; the NuttX
  runtimes build does not read it, and libcxxabi compiles against
  `runtime/libcxx/include` + `runtime/include_libc/cxx` instead — the same libc++
  the engine and the C++ deps (harfbuzz) use, which is what puts its typeinfo and
  exception symbols in the same `std::__sprt` as everything else in the image.
* `CMAKE_SYSTEM_NAME=Generic` for compiler-rt on Darwin (the Darwin cmake
  path produces empty archives). Compile `emutls.c` **into**
  `libclang_rt.builtins-aarch64.a` (baremetal builtins omit it). Never a
  side `libemutls.a`.
* Generic cmake installs libpng as `liblibpng16_static.a` / `libpng.a`. The
  inner Makefile stamps on `libpng16.a` — `common/libpng.mk` renames it
  (same as WASM).
* `libsprt.a` is NOT rebuilt when the in-tree runtime sources change - its rule
  depends on the staged builtins, not on `runtime/**` (same as target-wasm).
  After editing anything under `runtime/`, `rm` the archive from
  `intermediate/<triple>/usr/lib/` before re-running the assemble, or the
  target keeps the previous build and the change silently does not apply.
* Empty `runtime/toolchains/src/<lib>` directories satisfy make's directory
  target and skip the unpack. `src/freetype` with no `CMakeLists.txt` is
  this. `rmdir` and re-fetch.
* The export's `Make.defs` may carry an absolute `-Map=<nuttx-tree>/nuttx.map`.
  `import-export.mk` does not strip it; consumers that feed `NUTTX_LDFLAGS`
  into a link must filter `Map=` out.
