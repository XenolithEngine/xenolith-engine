# The 3d layer (basic3d)

A depth-tested 3d scene drawn under the basic2d UI of the same window: meshes with mip-mapped textures, an ambient light and a sun, seen through a camera that can be the isometric game camera or a perspective one.

**TL;DR**

- The scene is a [`basic3d::Scene3d`](../../../xenolith/renderer/basic3d/XL3dScene.h) with a [`basic3d::SceneContent3d`](../../../xenolith/renderer/basic3d/XL3dSceneContent.h); any number of [`basic3d::View3d`](../../../xenolith/renderer/basic3d/XL3dView.h) nodes in it show 3d views, and every basic2d node works as before, over them.
- A view draws [`Draw3d`](../../../xenolith/renderer/basic3d/XL3d.h)s: a [`Mesh3d`](../../../xenolith/renderer/basic3d/XL3dMesh.h), a transform and a `Material3d` (a colour times an optional `Texture`, tiled `uvScale` times).
- The [`Camera`](../../../xenolith/renderer/basic3d/XL3dCamera.h) is plain math: a target, a yaw, an elevation and a distance; orthographic in points per unit (times the density) or perspective; depth in [0, 1], clip y flipped for Vulkan. `project`, `unproject`, `screenRay`, `screenToGround` and `projectAabb` work in the scene's pixels, y up - the space of input locations and of `Node::getWorldBoundingBox`.
- Textures sample trilinear and anisotropic: give them mips (`core::MipLevelsFull` with `core::ImageHints::GenerateMipmaps`, which images decoded from files get by themselves).
- Local and Vulkan only, for now.

## Making a scene

```cpp
class MyScene : public basic3d::Scene3d {
public:
	virtual bool init(NotNull<AppThread> app, NotNull<core::RenderServerChannel> window,
			const core::FrameConstraints &constraints) override {
		if (!Scene3d::init(app, window, constraints)) {
			return false;
		}
		auto content = Rc<basic3d::SceneContent3d>::create();
		auto view = content->addChild(Rc<basic3d::View3d>::create());
		view->setContentSize(Size2(800.0f, 600.0f));
		view->addDraw(basic3d::Draw3d{basic3d::Mesh3d::makeTorus(2.0f, 0.7f, 64, 24),
			Mat4::IDENTITY, basic3d::Material3d{Color4F::WHITE, texture, 1.0f}});
		setContent(content);
		return true;
	}
};
```

[`examples/window/basic3d`](../../../examples/window/basic3d/main.cpp) is a complete one: a spinning textured torus over a ground plane, a translucent panel over both, mouse pan and wheel zoom on the view.

A view's camera, draws and lights change through its setters, which ask the window for a frame. A subclass with draws of its own (a terrain made of chunks) overrides `View3d::collectDraws`.

## How a frame gets to the GPU

1. `SceneContent3d` swaps basic2d's frame context for a [`FrameContext3d`](../../../xenolith/renderer/basic3d/XL3dFrameContext.h). Its handle is a `FrameContextHandle2d` with a list of views added, so every 2d node fills it as before.
2. `View3d::draw` sets its camera's viewport from its world rect and appends a `ViewInput3d`: the viewport, the camera's matrix and the lights, and the draws.
3. The context feeds the `Scene3dInput` attachment every frame, with no views when nothing was drawn: an input left unfed would stall the frame.
4. The [pass](../../../xenolith/renderer/basic3d/backend/vk/XL3dVkPass.h) packs every view's meshes into one vertex and one index buffer, with a buffer of draws and one of views, on a worker; the textures the draws use become the slots of its descriptor array. It draws before basic2d's pass, into the same `Output`, with a depth attachment of its own; basic2d loads what it drew.

Vertexes are read by `buffer_reference` through `gl_VertexIndex`; the layouts shared by C++ and GLSL are in [`XL3dGlslData.h`](../../../xenolith/renderer/basic3d/glsl/include/XL3dGlslData.h). Faces wind counter-clockwise seen from outside, and back faces are culled.

## Limits

- **No 2d children under a View3d.** They would be drawn as 2d content of the same frame, over everything.
- **64 textures a frame** (`basic3d::MaxTextures`). Draws past that show their colour alone, with a warning.
- **Views share one depth buffer**: two views that overlap test against each other.
- **Local only.** A remote client's queue is the server's, and basic3d does not add its pass there.
- **Vulkan only.** There is no WebGPU, Metal, GLES or software pass yet.
- **The 2d damage is off.** `Scene3d` uses basic2d's Default queue with damage tracking off, because the 3d pass repaints the whole frame.

## Tests

- `tests/basic3d` (`basic3dtest`, no device): the camera's math and the mesh builders.
- `tests/window/basic3d-check.py` drives the example headless: the torus drawn, textured and lit; the panel over it; the ground's fine checker even through the mips and aliased with `BASIC3D_NOMIPS=1`; no validation error.
- `tests/window/pass3d-check.py` checks the engine features under the module - a pass under basic2d, culling, depth bias and clamp, two subpasses - with a hand-made pass.
