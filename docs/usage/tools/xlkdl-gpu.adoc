# GPU schemas: `xlkdl gpu`

`xlkdl gpu` generates, from a schema written in KDL, two kinds of files:

* a **header** of records that C++ and GLSL both read, valid in both languages: as C++ through the
  types of `sprt_glsl.h`, as GLSL when `SP_GLSL` is defined;
* a **preamble** for each shader the schema names: everything the shader declares to read its
  pass's interface - extensions, push constants, buffer references, descriptors, varyings, its
  material - so the shader itself is an `#include` and a `main()`;
* for each **material** and **block**, besides its record, a C++ builder that makes it for a draw
  (`Material3d::data`) or a view (`View3d::setBlock`); for each **vertex**, a builder that packs it
  for a mesh (`Mesh3d::make`).

The schema of basic3d is [basic3d.kdl](../../../xenolith/renderer/basic3d/glsl/basic3d.kdl); the
basic3d example's, which imports it, is
[basic3d-example.kdl](../../../examples/window/basic3d/glsl/basic3d-example.kdl).

    make -C utils/xlkdl
    xlkdl gpu <schema.kdl>... [--out <file>] [--check]

A schema's header is written to its `output` and its preambles to its `preambles` directory, both
from the schema's directory; `--out` writes the header elsewhere, when a single schema is given.
`--check` writes nothing; the exit code is the number of files that are not what would be written.
A schema that does not load exits with 1 and `file:line:column: message` lines.

What a schema writes is committed next to it - the engine's and an app's alike. After a change:

    xlkdl gpu xenolith/renderer/basic3d/glsl/basic3d.kdl
    xlkdl gpu examples/window/basic3d/glsl/basic3d-example.kdl

`tests/run-checks.py` runs `--check` on both (`xlkdl gpu basic3d`, `xlkdl gpu basic3d-example`)
when a schema, what it writes or `utils/xlkdl` changed, and in the gate; `xlkdl` has to be built
for it, as a harness has.

**TL;DR**

* A **record** is a list of fields, laid out by **std430** - the layout of a storage buffer and of
  push constants. The generator computes every offset and the record's size.
* A field starts where the one before it ends. A gap std430 would leave is an error, since C++
  would not leave it: reorder the fields, or fill the gap with a field of your own.
* A record ends at its std430 size - a multiple of its largest alignment - with `uint` fields
  named `padding` (one) or `padding0`, `padding1`... (more).
* The header asserts the layout: `static_assert` on the size of every record and the offset of
  every field, so a C++ type that lays out differently from std430 does not compile.
* An **interface** is what a pass gives its shaders; a **shader** names its interface and its
  **varyings**, and gets a preamble, `<shader>.glsl`. A vertex shader and a fragment shader that
  name the same varyings declare the same interface block, so their locations cannot disagree.
* A **material** is a record of a pipeline's own data, which may have textures of a known kind;
  its builder makes a `MaterialData3d` a draw carries, the frame writes it once however many draws
  share it, and a shader that names it reads it by `material()`. A **block** is the same for a
  view: one a frame for all the view's draws, read by `block()`.
* A schema **imports** another to use its records, constants and interfaces; nothing imported is
  written again, and a preamble includes the header that defines the records it reads.
* Comments are part of the schema, as `doc=` - KDL comments do not reach the files. A doc of one
  line follows its field; one of several lines (a multi-line string) goes before it.

## The schema

```kdl
schema basic3d {
    output "include/XL3dGlslData.h"
    guard "XENOLITH_RENDERER_BASIC3D_GLSL_INCLUDE_XL3DGLSLDATA_H_"
    namespace "stappler::glsl"
    macro-prefix "XL_GLSL_3D_"
    copyright "2026 Xenolith Team <admin@xenolith.studio>"
    license "MIT"
    preambles "include"
}
```

One `schema` node per description, named by its argument, with:

| Child | Required | What it is |
|---|---|---|
| `output` | with records or constants of its own | the header, from the description's directory |
| `guard` | with records or constants of its own | the include guard |
| `namespace` | with records or constants of its own | the C++ namespace of the records, versioned (`namespace STAPPLER_VERSIONIZED …`), with `using namespace sprt::glsl` in it |
| `macro-prefix` | no | put before the name of every constant |
| `copyright`, `license` | no | the license block of every file: ` Copyright (c) …` and ` SPDX-License-Identifier: …` |
| `preambles` | with shaders of its own | the directory of the preambles, from the description's directory |

## Imports

```kdl
import "../../../../xenolith/renderer/basic3d/glsl/basic3d.kdl"
```

From the importing file's directory, or absolute. Every name is one definition across the files: a
record, a constant, an interface, varyings or a shader defined twice is an error, wherever the two
are. A file imported twice is read once; a file that imports itself through others is an error at
the import. An imported schema writes nothing; its records are included from its `output`, so a
schema with records of its own has an `output` even when it is only imported.

## Constants

```kdl
const NO_TEXTURE 0xFFFFFFFF type=uint doc="A texture field with no texture"
```

A constant is a `#define` of its prefixed name: `#define XL_GLSL_3D_NO_TEXTURE 0xFFFFFFFFu`. Its
`type` is `uint` (an integer that fits 32 bits, written with `u`), `int` (a signed 32-bit integer)
or `float` (a float literal). The number is written as it was typed, without KDL's `_` digit
separators.

## Records

```kdl
record ViewData3d doc="One view: its camera and its light" {
    viewProj mat4 doc="depth in [0, 1], clip y flipped for Vulkan"
    sunDirection vec4 doc="""
        xyz - toward the sun,
        unit length
        """
    screen vec4
    firstLight uint
    lightCount uint
}
```

A record is a `struct`; each child is a field, named by the node, its type the argument. `count=N`
makes it an array. In a material, a block or a vertex, `default=` gives a scalar field the value
its builder starts with (`uvScale float default=1`); with none it starts at 0.

| Type | Size | std430 alignment | Arrays |
|---|---|---|---|
| `float`, `int`, `uint` | 4 | 4 | yes |
| `vec2`, `uvec2` | 8 | 8 | yes |
| `vec3`, `uvec3` | 12 | 16 | no: an array steps 16 bytes in std430 and 12 in C++ |
| `vec4`, `uvec4`, `color4` | 16 | 16 | yes |
| `mat4` | 64 | 16 | yes |

The C++ alignment of a type may be smaller than std430's (`UVec2` aligns to 4): the padding the
generator adds and the asserts it writes keep the sizes equal.

## Materials

```kdl
material Glass3d doc="The tinted glass of the translucent pipeline" {
    color vec4
    depthRange float
    density float
}
material Terrain3d { tint vec4; ground texture-array; detail texture2d; params vec4 count=2 }
```

A material is a record, laid out as one, whose fields may also be textures: `texture2d` (a slot of
the texture array) or `texture-array` (one of the layered array), one texture each. In the record
and in GLSL a texture field is the `uint` slot the pass writes for the frame, or the schema's
`NO_TEXTURE`. A record of the schema with a material has its `output`, and the header includes
`XL3dMaterial.h` for C++ and writes, for each material, a builder:

```cpp
struct Terrain3dMaterial {
	vec4 tint;
	xl3d::MaterialTexture3d ground; // Rc<Texture>
	xl3d::MaterialTexture3d detail;
	vec4 params[2];

	static constexpr xl3d::MaterialTextureField3d Textures[] = {...};
	static constexpr xl3d::MaterialSchema3d Schema{"Terrain3d", 64, 16, Textures, 2};

	sprt::Rc<xl3d::MaterialData3d> make() const; // the record and the textures, in their order
};
```

`Schema` is what a pipeline that reads the material names (`Pipeline3dInfo::material`) and what
the pass compares a draw's material with, by address; `make()` is what a draw carries
(`Material3d::data`, see [the basic3d guide](../basic3d/overview.adoc)).

## Vertexes

```kdl
vertex Compact3d position=pos doc="A box's vertex: 16 bytes" {
    pos vec3
    normal oct16
}
```

A vertex is a record of a mesh's vertexes, its fields of a record's types or packed, a `uint` in
the record and in GLSL:

| Type | Holds | C++ packs by | GLSL unpacks by |
|---|---|---|---|
| `oct16` | a unit `vec3`, octahedral, in two snorm16 | `basic3d::packOct16` | `xl3dUnpackOct16` (in the preamble) |
| `half2` | a `vec2` in two halves | `basic3d::packHalf2` | `unpackHalf2x16` |
| `unorm8x4` | a `vec4` from 0 to 1, a byte each, x in the lowest | `basic3d::packUnorm8x4` | `unpackUnorm4x8` |

`position=` names a `vec3` or `vec4` field: the mesh's bounds are taken from it. A vertex has no
arrays and no textures. The header includes `XL3dVertex.h` and writes a builder, `<Name>Vertex`,
with the fields unpacked, the `Format` (`VertexFormat3d`: stride, alignment, the position's offset)
and `pack()`; `Mesh3d::make<Compact3dVertex>(vertexes, indexes)` makes a mesh of them. A vertex
shader that names it (`vertex=`) gets the GLSL `<Name>Vertex`, unpacked, and `<Name>Vertex
vertex(uint i)`, through the interface's `vertex pointer=`.

## Blocks

```kdl
block Example3dView doc="What the example's view gives the pipelines that read it" {
    depthRange float doc="the camera's far - near"
}
```

A block is a material of a view rather than of a draw: the same rules for its fields, textures
included, and a builder `<Name>Block` with its `Schema` and `make()`. A view takes what `make()`
returns (`View3d::setBlock`), a pipeline that reads it names its schema (`Pipeline3dInfo::block`),
and its shaders read it by `block()`.

## Interfaces

```kdl
interface pass3d doc="The 3d pass: ..." {
    push-constants Constants3d name=constants
    buffer vertices Vertex3d pointer=vertexPointer
    buffer draws DrawData3d pointer=drawPointer
    buffer view ViewData3d pointer=viewPointer single=#true
    buffer lights LightData3d pointer=lightPointer
    samplers textures sampler2D binding=0 count=MAX_TEXTURES
    samplers textureArrays sampler2DArray binding=1 count=MAX_TEXTURE_ARRAYS
    depth sceneDepth binding=2 index=0
}
```

| Child | What a preamble declares |
|---|---|
| `push-constants <record> name=<n>` | `layout (std430, push_constant) uniform PushConstants { <record> <n>; };` |
| `buffer <name> <record> pointer=<field>` | a `buffer_reference` block `<record>Buffer` holding `<record> <name>[]` (or one, with `single=#true`), and a function to read it: `<record> <name>(uint i)` or `<record> <name>()`, from the address in the push constants' `uvec2` field |
| `samplers <name> sampler2D\|sampler2DArray binding=N count=…` | in a fragment shader, `layout (set = 0, binding = N) uniform … <name>[count]`; the count is a number or a constant |
| `depth <name> binding=N index=I` | in a translucent fragment shader, `layout (input_attachment_index = I, set = 0, binding = N) uniform subpassInput <name>` |
| `material pointer=<field>` | in a shader that names a material, a `buffer_reference` block `<material>Buffer` holding one, and `<material> material()` from the address in the push constants' `uvec2` field |
| `block pointer=<field>` | in a shader that names a block, `<block>Buffer` and `<block> block()`, likewise |
| `vertex pointer=<field>` | in a vertex shader that names a vertex, `<vertex>Buffer` of them, the unpacked `<vertex>Vertex` and `vertex(uint i)` |

A vertex shader gets no samplers and no depth, a fragment shader of an opaque pipeline no depth:
the pipeline's layout is made from what the SPIR-V declares, and a translucent pipeline's alone has
the depth.

## Varyings and shaders

```kdl
varyings Mesh3dVaryings doc="What the mesh pipeline's vertex shader hands its fragment shader" {
    normal vec3 doc="in the world, not normalized"
    texCoord vec2
    world vec3
}

shader xl_3d_mesh.vert interface=pass3d varyings=Mesh3dVaryings
shader xl_3d_mesh.frag interface=pass3d varyings=Mesh3dVaryings
shader basic3d_glass.frag interface=pass3d varyings=Stripes3dVaryings translucent=#true \
    material=Glass3d
```

Varyings are an interface block, `out` of a vertex shader and `in` a fragment one, named `vary`:
`layout (location = 0) out Mesh3dVaryings { vec3 normal; … } vary;`. Its members take locations in
their order. A varying is a scalar or a vector; an integer one is `flat`, and `flat=#true` makes a
float one so.

A shader is named by its file - a name, then `.vert` or `.frag` - and its preamble is that name
with `.glsl`. `material=` names the material its pipeline reads, `block=` the view's block, and,
for a vertex shader, `vertex=` the format of its meshes; its interface has to give them. A fragment shader also gets `layout (location = 0) out vec4 outColor;`. The shader
includes its preamble after `#version` and the include directive:

```glsl
#version 450
#extension GL_GOOGLE_include_directive : enable

#include "xl_3d_mesh.vert.glsl"

void main() {
	Vertex3d v = vertices(gl_VertexIndex);
	DrawData3d d = draws(constants.drawIndex);
	vary.normal = (d.normal * vec4(v.normal.xyz, 0.0)).xyz;
	gl_Position = view().viewProj * (d.model * vec4(v.pos.xyz, 1.0));
}
```

The directory of the preambles has to be on the shaders' include path: a module's
`MODULE_<X>_SHADERS_INCLUDE`, an app's `LOCAL_SHADERS_INCLUDE`. It cannot be the shaders'
directory itself, where the build compiles every file with a dot in its name.

## Errors

Every one carries its place in the description:

* an unknown node, property or type; a node with the wrong number of arguments;
* a name that is not an identifier, or a name defined twice;
* a field that would start past a gap, or an array of a type that steps differently in C++;
* a record whose padding would take the name of one of its fields;
* a constant whose value does not fit its type;
* an import that is not there, or an import cycle;
* a record, an interface, varyings or a constant a definition names and no file defines;
* a buffer whose pointer is not a `uvec2` field of the push constants;
* a sampler type other than `sampler2D` and `sampler2DArray`;
* a varying that is not a scalar or a vector; a shader name that is not `<name>.vert` or
  `<name>.frag`; a translucent vertex shader;
* a texture field outside a material or a block, or an array of them; a shader's `material=` or
  `block=` that is not one, or whose interface gives none; a material's or a block's pointer that
  is not a `uvec2` of the push constants;
* a packed type outside a vertex, an array in a vertex, a `position=` that is missing or no `vec3`
  or `vec4` field, a `vertex=` on a fragment shader or naming no vertex.
