# File layout: license, include guards, namespaces, includes

**TL;DR**

* Every source/header starts with the MIT license block in a `/** … **/` comment.
* Include guard = path from the repository root, uppercased, `/` and `.` → `_`,
  with a trailing underscore: `XENOLITH_RENDERER_UI_ATOMS_XLUIBUTTON_H_`.
* Application namespaces are opened as
  `namespace STAPPLER_VERSIONIZED stappler::<module>… {`; runtime code lives in
  plain `namespace sprt`.
* Exported entities are marked `SP_PUBLIC` (stappler/xenolith) or
  `SPRT_API` / `SPRT_GLOBAL` (runtime).
* `SortIncludes` is off in clang-format — include order is yours to maintain,
  and it is significant in SCU builds.

## License header

Every file opens with the MIT block, wrapped in `/** … **/` (two asterisks at
the end), followed by a blank line. The copyright holder differs per subtree —
copy it from a *neighbouring* file rather than from this document:
`runtime/` and `stappler/` files say *Stappler Team <admin@stappler.org>*,
newer `xenolith/` files say *Xenolith Team <admin@xenolith.studio>*.

## Include guards

Header guards are derived mechanically from the path relative to the repository
root. There is no `#pragma once`.

[cols="2,3"]
|===
| File | Guard

| [xenolith/application/nodes/XLNode.h](../../../xenolith/application/nodes/XLNode.h)
| `XENOLITH_APPLICATION_NODES_XLNODE_H_`

| [stappler/data/SPData.h](../../../stappler/data/SPData.h)
| `STAPPLER_DATA_SPDATA_H_`

| [runtime/include/sprt/runtime/ref.h](../../../runtime/include/sprt/runtime/ref.h)
| `RUNTIME_INCLUDE_SPRT_RUNTIME_REF_H_`
|===

The closing `#endif` carries the guard name as a trailing comment:

[source,cpp]
----
#endif // RUNTIME_INCLUDE_SPRT_RUNTIME_REF_H_
----

## Namespaces

Application-level code (stappler + xenolith) opens its namespace through the
`STAPPLER_VERSIONIZED` macro, which optionally injects an ABI version prefix
(see [SPPlatformInit.h](../../../stappler/core/detail/SPPlatformInit.h)):

[source,cpp]
----
namespace STAPPLER_VERSIONIZED stappler::data { … }
namespace STAPPLER_VERSIONIZED stappler::xenolith { … }
namespace STAPPLER_VERSIONIZED stappler::xenolith::ui { … }
----

Never write `namespace stappler::…` without the macro in a header: with a
versionized build the resulting symbols land in a different namespace than the
rest of the SDK and fail to link.

Runtime code (`runtime/include/sprt/…`, `runtime/core/…`) is *not* versionized
and uses `namespace sprt { … }` directly. Internal helpers go into a nested
`detail` namespace.

`FixNamespaceComments` is on, so clang-format maintains the
`} // namespace stappler::xenolith::ui` trailer.

## Visibility macros

| Macro | Where | Meaning |
|---|---|---|
| `SP_PUBLIC` | stappler / xenolith | exported from the shared library (dllexport/dllimport/visibility, see [SPPlatformInit.h](../../../stappler/core/detail/SPPlatformInit.h)) |
| `SPRT_API` | runtime | exported runtime API |
| `SPRT_GLOBAL` | runtime | exported entity that must have a single global instance across modules |

Mark classes and free functions that cross a module boundary; purely
header-inline templates need nothing.

## Includes

`SortIncludes: Never` — clang-format will not reorder includes, deliberately.
In an SCU build the order is semantically load-bearing (a subunit can rely on
what the parent SCU included before it), so keep the existing grouping and
append rather than "tidy up".

Conventions visible across the tree:

* Project headers use quotes and a bare filename (`#include "XLUiStyleResolver.h"`),
  relying on the include paths the build sets from `LOCAL_INCLUDES_DIRS` /
  `LOCAL_INCLUDES_OBJS`.
* Runtime headers use angle brackets with the full logical path
  (`#include <sprt/runtime/stringview.h>`, `#include <sprt/cxx/atomic>`).
* An SCU aggregator includes its common header first, then the subunits in
  dependency order — see
  [xenolith/renderer/ui/XLUi.scu.cpp](../../../xenolith/renderer/ui/XLUi.scu.cpp):

[source,cpp]
----
#include "XLCommon.h" // IWYU pragma: keep

#include "style/XLUiStyleSheet.cc"
#include "style/XLUiStyleSystem.cc"
#include "style/XLUiStyleResolver.cc"

#include "layout/XLUiLayoutSystem.cc"

#include "atoms/XLUiInteractiveComponent.cc"
#include "atoms/XLUiButton.cc"
----

* Add `// IWYU pragma: keep` to an include that looks unused but is required
  (umbrella/PCH-like headers), so tooling does not strip it.
